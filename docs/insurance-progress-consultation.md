# 門市保險進度請益契約

門市 16:00、21:00 各自使用正式日報的店級手機保險搭售率。來源是 `搭售達成率 (手機保險)` H 欄，不是 G 欄進度達成率、當日分子／分母或個人分頁。每日原輸入與晚間 A999／好速／R1399 零報請益維持獨立；個人回報與考核不變。

正式有效且適用的月累計率低於 50% 時，五欄 trim 後必須非空：請益對象、破冰方式、運用工具、建議話術／作法、執行提醒／待確認。0% 適用，50% 不觸發，判斷不採顯示率的四捨五入。缺值、未核實期間、跨月或較早批次明示待核，不從個人表或 KPI 推斷期間。只有原公布率時直接使用，不反推分子母。

## 候選資料路徑

`extract.py` 自動建立私有 `meta.storeInsuranceProgress`，透過原 KPI 發布管線交付；表單從原 B 登入成功的 KPI bundle 取得。原排程、郵件、產圖和發布器未更改；新的欄位尚需在正式管線部署並驗證保留。此候選不新增公開資料檔、讀取端點或權限。

目前的期間驗證只接受同一店級分頁上的明確統計期間文字。現有產圖流程曾從個人分頁取期間，該值不會被新請益判斷採用。來源檔與發布日期、SHA、版本必須與私有 KPI 容器一致，門市須與同檔正式代碼及別名對應。來源更正會產生新版本；同一原報重跑得到相同內容，不建立歷史或新增寄信。

## 儲存與編輯

Google Sheet 只按欄名在最右側追加 `insurance_consult_json`，不移動既有聯名卡欄。內含判定用進度、來源與五欄；非適用狀態不儲存殘留請益文字。舊列不回填。首次送出在原提交鎖內重核私有正式來源；來源已改變時要求重新讀取，防止舊預覽判斷套入新批次。相同 mutation ID 沿用原去重，不因重試再次寫入。

已保存的同店／同日／同時段編輯保留當次判定來源；之後正式來源升高不改判過去回報。其他時段使用各自第一次保存時的來源。原回報的歷史讀取不會觸發新判斷或補寫。來源未接通且舊客戶端未帶新欄時維持相容；已發布有效來源的首次提交須與已登入表單讀到的版本相符，不接受客戶端自填率或偽造來源。

## 發布前與回復

1. 使用每日回報實際現役專案，完整備份部署版與編輯版（包含 manifest、編輯器獨有檔），逐片段對照；repo 並非正式完整備份。保留聯名卡及其他 Console-only 改動。
2. 在私有副本加入 `InsuranceConsultation.gs`，只套用 `Code.gs` 的追加欄名、來源判定與 store write hook；不整檔覆蓋。新 shared core 必須與前端同版。現有 manifest 不改。
3. 正式受保護日報發布管線先驗 metadata 沒被丟棄、來源同批與統計期間；未知期間只能發布 pending，不為了啟用規則填造 cutoff。
4. 後端新部署確認原 URL／權限，前端再發布；在未有權威期間前維持 pending 相容模式。不得單獨啟用有效必填來源而讓仍用舊前端的門市無法送出。
5. 用正式登入驗兩時段與督導彙整，實際寫回只用真實回報，不寫測試店／假數字。首次真實保存後核對來源凍結、五欄、原回報及聯名卡讀回。
6. 回復時先停止新 sidecar 的啟用（不改既有日報排程），回復原部署指標及前端版本。保留新增欄及既有值，不刪欄、不移欄、不回填；既有程式按欄名存取仍相容。

發布門檻：店級期間權威證據、正式管線保留 sidecar 的讀回、實際部署的完整備份及正式登入。合成測試或公開資產檢查不能取代這些條件。
