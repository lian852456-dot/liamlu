# 第一階段量測收據

以下數據是10/13的隔離合成量測。2026-10-16舊快照成本修正及最新正式驗收缺口見[跟進說明](DEPARTMENT_FAST_READ_PHASE1_FOLLOWUP.md)；不將原文當時的未部署狀態沿用為今日狀態，也不以本輪呼叫減少宣稱正式秒數改善。

狀態：本機候選及合成驗證完成；正式服務量測、正式資料對帳、實體手機驗收與發布未完成。

基準為正式 `11907891f218f0b3ee51b67373a8def474550e97`，公開六資產已核對相符。候選各 sample 的資產 SHA-256 已與目前程式逐檔比對，完整數值及來源版本見 [performance.json](evidence/department-fast-read-phase1-20261013/performance.json)。

測試資料為金牌 3 個月 × 160 位合成人員（每區 40 人）、成績 6 個月 × 9 間合成店（A/B/C/D = 2/2/2/3）。使用 Chromium／WebKit，桌機 1440×1000 與手機 390×844，四組各做三個冷頁樣本。固定模擬延遲：auth 80ms、金牌 full/version 200/80ms、成績 full/version 600/80ms。時間包含 UI 操作、等待與呈現；載入完成須能看到 dashboard，返回還須等待驗權遮罩結束。這些不是正式 GAS 網路時間，也不是實體 iPhone 測試。

已載入頁籤／月份／四區／店點／明細切換的全樣本最大值為 **408ms**，低於 500ms；每次均驗證兩個資料域的 API 增量為 0。A/B/C/D 分別實際切換並核對列數；單月與季度亦各自切換。原版篩選已是前端計算，因此不把這一項稱為新增省略 GAS 的成果。

## API 次數與重試

| 同一完整操作腳本，每個樣本 | 基準 | 候選 |
| --- | ---: | ---: |
| 所有 API（含既有提醒 sidecar） | 13 | 14 |
| 完整金牌／成績資料回應 | 7 | 4 |
| 帶已知版本的讀取 | 0 | 7 |
| no-change 短回應 | 0 | 5 |
| 單次成績返回讀取 | 1 | 1 |
| 三個同步返回事件的成績讀取 | 1 | 1 |

總 API 增加一次，是因候選在回到另一個已載入資料域時也補做該域的版本核對；基準金牌返回只有 session auth，沒有更新資料版本。正式要求的權限與版本核對不能省略。主要收益是完整資料回應由 7 次降為 4 次，及成績返回等待降低；不是所有 API 次數下降。提醒 sidecar 的獨立請求保持原樣。

合成正常路徑沒有重複成績請求；故障回歸另外驗證三次重試上限、75 秒期限、每次獨立傳輸 ID、舊回應取消及寫入不重送。正式 `department_scores_read` 的執行內部耗時與真實重試情況仍待有效督導登入後量測，不能由合成路徑推定。

## 測試與驗收層級

- Node 單元／資料／ACL／版本／寫入完整讀回／PPT core：67 項通過。
- Chromium：原有 81 情境，加金牌 busy 保護 1、讀取 lifecycle 8，共 90/90 通過。
- WebKit：40/40 既有及 lifecycle 情境通過，包括桌機／手機版面；屬瀏覽器引擎與 viewport 模擬。
- A/B 性能：基準 4/4、候選 4/4 projects，各含三次樣本，合計 24 個 profile。
- 既有 PPT／PDF browser 檢查：9/9，含 native editable PPTX、篩選、撤權取消與多頁溢位內容保留。
- 視覺 QA：金牌／成績桌機與手機安全合成截圖已檢視；保留既有排版及業務入口。
- 基準 integration 的收合提醒登出測試原有 1 項不可見失敗；候選修正測試先展開再點登出，產品功能未改。

## 尚待正式驗收

2026-10-13 正式頁可開啟，但停在督導登入；未讀取或搬移 credentials。正式來源資料量、auth／資料／render 分段、實際 API 請求次數及受保護資料對帳均未驗證。首次正式載入目標尚未訂定，須依這些實測結果決定。合成首次金牌約 0.57–0.63 秒、成績約 0.92–0.94 秒，只描述這個固定 fixture。

實體 iPhone Safari／PWA、長背景、離開後返回、登入到期、登出、切換身分、管理撤權，以及正式原檔上傳／回復／Excel／PPT，均須在適當授權的候選環境驗收後，才可決定精確發布範圍。本 PR 維持待驗收；正式 GAS、部署及營運資料寫入 0。
