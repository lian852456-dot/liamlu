# 每日日誌檢查儀表板

## 目前狀態

- 狀態：GitHub Pages 候選版已發布；仍是本機檔案解析，尚未串接雲端寫入。
- 入口：`home.html` 的「同仁大廳」→「每日日誌檢查」。
- 資料行為：使用者選擇本機 Excel／CSV 後，只在瀏覽器解析；套用結果存於目前裝置的 `localStorage`。
- 原始系統仍是唯一資料來源；候選版不會修改公司表單或 Google Sheet。
- HTTPS 功能驗證：已在正式 Pages 網址由「同仁大廳」進入，並以合成 `.xlsx` 完成原生選檔、解析、套用與重新進頁後讀回；網站 console 無錯誤。手機版與真實去識別化報表仍待驗收。

## 來源資料契約

目前依使用者提供的報表截圖辨識下列欄位，解析器也接受少量同義表頭：

| 必要性 | 標準欄位 | 用途 |
|---|---|---|
| 必要 | 店點 | 對應北一二B九店 |
| 選用 | 填寫人員 | 明細顯示 |
| 選用 | 填寫時間 | 判定每日日期及最後填寫時間 |
| 必要 | 檢查項目 | 對應十張已確認表單 |
| 必要 | 處理狀態 | 已完成／未完成／待確認 |
| 選用 | 大項名稱 | 長細項分組 |
| 必要 | 細項名稱 | 明細展開內容 |

若報表缺少填寫時間，使用者必須先選擇資料基準日。未知店點會整批阻擋預覽；未知表單不會混入完成率，會另列為待確認。

## 儀表板規則

- 每日總覽：九店 × 四項，共 36 項。
- 每週總覽：九店 × 第一至第四週，共 36 項。
- 每月總覽：九店 × 兩項，共 18 項。
- 尚未到期且沒有紀錄的週／月表顯示「未到期」，不列入「需追蹤」。
- 已到期的缺資料、未完成或未知狀態列入「需追蹤」。
- 點擊門市卡可展開原始大項、長細項、填寫人及最後填寫時間。

## 本機更新流程

1. 選擇資料基準日。
2. 選擇 `.xlsx`、`.xls`、`.csv` 或 `.tsv`。
3. 頁面以 repo 內固定版本 SheetJS 在本機解析，不使用 CDN。
4. 預覽辨識列數、門市數及未知表單列。
5. 使用者確認後套用到目前裝置的九店儀表板。
