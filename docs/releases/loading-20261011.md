# Website and App loading patch

The password entrance previously checked status and session before reading two
protected datasets. Those reads already enforce the same server-side session,
device, roster, expiry, suspension and revocation rules under the GAS lock. Home
also started both reads eagerly; opening KPI before they completed started them
again, and a retained legacy identity could launch a competing legacy read.

The patch removes the eager reads and duplicate status check. An uncached
ordinary page sends its two protected reads together. A cached page or a
background return validates its session before showing retained data. Installed
owner-phone App startup still validates eligibility, alongside the reads.
Concurrent identical protected requests share one in-flight operation; logout
invalidates that operation and prevents late responses from restoring data.

The five App tabs already shared one document and issued no data requests on
selection. They now retain their scroll positions and rendered icons as well as
their existing filters and expansion state. Backgrounding hides protected content
without rebuilding it. A failed return validation clears it. The existing local
expiry, server checks, 60-second foreground validation interval, cache TTL and
phone grant/logout rules remain in force. Remote changes are discovered on the
next server validation or protected request; no instantaneous push revocation is
introduced.

No GAS source, roster renewal, formal data, device binding, session limit, or
credential settings are changed by this patch. Rollback is a revert of the patch
commit, with a fresh service-worker cache version. The pre-patch frontend source
is `d5a93c2edd76e176a04b0b331c8eb9a9bd500234`; subsequent unrelated main changes
must be retained when reverting.

## Measurement and acceptance

The optional **載入計時** control records at most 100 allowlisted operation labels,
durations, timestamps and outcomes. It contains no identity, credentials, URLs,
request bodies, or business data. Enabling persists on the device; events stay in
the current tab's session storage. **停止計時** removes persisted diagnostics.
The request count is B API requests only, excluding static assets and independent
Patrol calls. `phase:render` is synchronous view rendering. `phase:ready` includes
two animation frames and measures from login submission or document navigation
for restores. `phase:validate` includes transport and server validation;
`phase:data` includes transport, server authorization and data reads. Pure server
CPU authorization/read time is not separately instrumented.

Controlled Chromium fixtures verify request counts, state preservation,
background masking, failed authorization, logout races, owner-phone reopen, and
home → KPI → awards → personal. They do not establish physical iPhone speed or
production authorization acceptance. Release asset readback and a fresh iPhone
Safari/installed App pass after the latest roster update are separate gates.

The physical comparison must use the same iPhone and network for first KPI,
App reopen, and both rounds of five tabs. Logout, expiry, disabled access and
revocation must also be checked on that device. Unexecuted scenarios remain
explicitly pending; do not substitute earlier phone evidence or synthetic tests.
