## 可重現問題與修正

- 門市草稿原只存在分頁記憶體。現在依服務網址、門市、日期、時段保存本機草稿；重新整理、關頁後可取回。首次讀取失敗時仍保留修改，完成正式讀取前維持送出限制。登出／切換登入清除表單草稿。
- 個人回報原先只在背景 pwrite 失敗時寫 console，沒有可操作重試。現在分別顯示本機、核對中、上傳中、雲端確認、未送出及結果未確認，提供原提交的確認／重試入口；成功前不把本機紀錄標成雲端確認。
- 門市日期若為 Sheets Date 物件，原寫入的字串比對找不到原列；門市、個人及台獎的同鍵多列原寫第一列、讀最後列。現在統一日期正規化，更新讀取所採用的最後同鍵列。保留歷史列，不刪除或清理正式資料。
- 原寫入沒有逾時邊界及提交識別。新增 `report-save-v1`：本機 journal 先保存原提交，30 秒內未取得可核對回應視為結果未確認。途中切換服務網址仍保留原端點 journal 並維持未確認；不同提交不清除彼此的 journal。人工重試先讀回提交識別，已成功只確認、不再寫；未成功才用原識別及原基準版本重試。ScriptLock 包住版本比較、寫入及讀回，較新的版本不被舊重試覆蓋。
- 讀取徽章改為「已讀取雲端資料」；原「本時段已填資料」改為「先前回報紀錄；本次修改請另確認儲存」。本次修改的儲存狀態持續顯示於送出區，避免與讀到既有紀錄混淆。
- 個人未過關說明與門市零報待送出資料固定原日期、店別及時段；切換上下文後不把原資料送到另一時段。

## 相容性與提交證據

新增唯讀 POST action `report_save_status`，只讀既有回報來源。寫入仍使用原 `write`／`pwrite`；新請求附 `mutation: {schema,id,baseRevision}`。回應包含 date/store/seg、個人 name、commitId、伺服器 committedAt 與正式 readback。

門市來源以既有自動補欄位流程新增 `_report_commit_id`、`_report_committed_at` 兩個證據欄；個人證據保存在原 record JSON 的 `_report_commit`。未變更業績欄位定義、考核門檻、11 月管理設定、金牌、班表、權限或憑證。

原前端仍可呼叫更新後的後端。新前端若遇舊後端，會在唯讀核對階段停止，保留草稿，不盲目送出。版本衝突可先備份草稿、重新讀取雲端，再取回草稿供人工核對；不自動採用舊草稿覆寫。

Sheets 多表寫入不是資料庫交易。若核心／台獎或提交證據在中途失敗，不宣稱完整成功；保留本機提交，要求讀回及人工核對。
