# 正式城市導入準備（尚未執行）

本計畫僅供審閱。本輪只修改獨立驗收室；正式城市仍維持既有版本，未植入新人物、開關、資產或資料變更。Blender V2 美術方向已獲使用者認可，但完整人物美術與實體 iPhone Safari 尚未完成導入驗收。

## 1. 固定資產與替換範圍

- 以 db15e88 內的 Blender V2 GLB、原版眼睛、精緻皮膚及已定版2.5頭身為不可變基準；保存 .blend、建模腳本、GLB、貼圖及SHA清單。
- 正式套件僅帶V2與舊renderer fallback；不帶V1、比較截圖及工作室燈光。GLB僅替換短髮，不把整個頭部當作髮型資產匯入。
- 第一階段限指定一個既有角色。其他髮型、NPC、交通工具騎士及未授權角色保持既有factory。照片專屬avatarPreset另列相容驗收，不能用通用示範頭部覆蓋本人造型。
- 使用同一版本資產清單與不可變網址；共用一次載入promise、geometry與貼圖，每個角色僅有必要的髮色材質。載入失敗／context異常時回到舊renderer，顯示明確提示，不清除角色。

## 2. 存檔與多人契約

- 保留既有hair／outfit／skin／character／avatarPreset、背包ownership、錢包、金幣ledger、寵物、家具與合法位置；沒有DB schema migration需求，也不改價格、正式金牌、登入或權限。
- renderer版本、全身取景、光線預覽、QA actor清單與功能旗標不得寫入profile或同步封包。舊client仍須能讀同一份存檔。
- 遠端人物也必須由相同的角色ID＋本機renderer策略選擇factory，不靠新增profile欄位。本候選已提供指定合成actor的peer opt-in以便驗證；正式城市的伺服器配置尚未接入。
- 上線前用唯讀備份副本完成舊client／新client交叉reload、已購髮型／服裝、特殊avatarPreset、寵物／家具與兩裝置同步的相容檢查；驗證原始資料指紋與唯一獎勵收據。不能拿空白新帳號代替既有角色相容驗收。

## 3. 開關與階段

1. 實體iPhone與完整人物美術驗收通過後，再提出實際正式城市小範圍patch供使用者確認；本輪不部署。
2. 正式開關預設關閉，包含全域enabled、指定角色allowlist、髮型bob限制及資產版本。不可因網址參數就替任何角色取得新造型或權限。
3. 先讓一個經確認的既有角色開啟；兩個裝置必須看見相同V2髮型與裝備。監看載入失敗、context loss、畫面時間與資源數。
4. 單人與遠端顯示穩定後，再評估少量同仁。全城／41個NPC不得直接一起換成精緻人物；可見人數、距離與LOD需先有同場負擔證據。

## 4. 回復機制

- 本候選的CozyAvatarCandidate.setEnabled(false)可讓已選的本機／QA peer回到原角色factory；重新啟用會套回同一profile。此接口已在隔離環境演練，不代表正式城市已植入開關。
- 正式發布需保留舊資產清單、舊JS bundle及固定回復版本。發現閃白、掉context、模型缺失或同步異常，先關指定角色／全域旗標，再重新載入舊bundle。
- 必須釋放舊角色實例、材質及GLB快取；不能只把mesh隱藏。需要重新進頁以清除快取時保留正常登入與存檔，不要求清Cookie或重建角色。
- 這是渲染回復，原則上不回復資料庫，避免覆蓋期間新購物／家具／位置紀錄。備份只供資料毀損事故處理，不用於平常美術切換。
